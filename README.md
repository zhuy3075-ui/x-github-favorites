# X GitHub Favorites

在 Chrome 阅读 X / Twitter 时，点击帖子旁的 **＋**，将 GitHub 仓库链接和帖子原文收藏到自己的飞书多维表格。适合积累开源工具、保留推荐出处，减少打开仓库、复制链接和手动整理的步骤。

当前版本：**0.2.0 联调候选版**。本机 41 项自动测试通过，类型检查、构建及 Manifest 检查通过；真实飞书新增、重复收藏和读回尚待验收。公开仓库的 `test` 分支保存当前开发状态，不表示正式发布。

## 功能

- 同帖多个 GitHub 仓库分别存一行，仓库子路径归一去重。
- 保存原文、原帖链接、作者名称、@账号、发布时间和采集时间。
- 分开保留入口帖和直接引用的一层来源；引用中的仓库使用引用帖作者及原文。
- 已保存的同帖版本显示已收藏；新帖子提到已有仓库时只追加来源，保留人工修改的主字段。
- 支持进入 X Article 详情后读取文章标题、正文及发布时间。
- 提供连接设置、字段映射、最近任务、逐仓库结果、重试和复制。
- 写入结果不明时保留任务并只读核对，避免响应丢失后重复提交。

原文按实际页面保存，不使用 AI 生成用途简介、分类或摘要。多仓库同帖会共享正文，不判断哪句话对应哪个仓库。

## 当前限制

推荐流只显示文章预览或截断正文时，**需要进入帖子正文后再收藏**。自动后台详情补读仍有超时重试竞态，正式任务未启用该路径；源码中保留相关实验实现，不应直接接入生产流程。

不采集整个时间线，不读取外链文章或 GitHub README，不做 OCR，也不递归读取深层引用。当前面向单用户、单 Chrome 配置文件；跨设备并发不保证原子去重。X 页面改版可能需要更新来源适配。

## 快速开始

需要 **Chrome 120+、Node.js 24 和 npm**。

```sh
git clone --branch test https://github.com/zhuy3075-ui/x-github-favorites.git
cd x-github-favorites
npm ci
npm run build
npm run check:manifest
```

1. 在 Chrome 打开 `chrome://extensions`，启用开发者模式。
2. 点击“加载已解压的扩展程序”，选择构建出的 `dist` 文件夹。
3. 准备自己的飞书多维表格，按[字段说明](docs/FIELDS.md)创建 16 列。
4. 在插件设置中填写自己的多维表格 `/base/` 链接及本表 **PersonalBaseToken**，检查连接、确认字段映射，再保存设置。
5. 刷新已经打开的 X 页面，找到包含 GitHub 链接的帖子，点击动作栏旁的 **＋**。

PersonalBaseToken 通常以 `pt-` 开头，从多维表格的开发／插件相关入口取得。飞书 CLI 的 OAuth 登录、应用 App Secret 和本表授权码是不同凭证。

仓库提供源码及构建配置；`dist`、安装包、依赖缓存和个人表格配置不随源码提交。更新源码并重新构建后，在原扩展卡片点击“重新加载”，再刷新 X 页面。

## 日常使用与结果

点击收藏后可以继续阅读，结果保存在工具栏插件的“最近任务”中。“查看详情”可检查每个仓库、入口与引用原文以及缺项。

| 状态 | 含义及操作 |
|---|---|
| 已收藏／已补来源 | 来源已核验保存；同帖同版本不再新建行 |
| 部分完成 | 已知仓库可能已保存，检查缺项或失败项再重试 |
| 没有仓库／正文未完整读取 | 若文章仅显示预览，进入正文再收藏 |
| 待核对 | 上次写入可能已生效；只读取证明，避免重复提交 |
| 设置已变更／重启中断 | 任务保留，切回原目标后按需重试 |

X 自带书签与 Favorites 独立。不要删除“来源记录”中的版本化文本块，否则插件会失去该来源的收藏证据。

首次使用请核对飞书新增行中的仓库、原文和作者；再次查看同帖应显示已收藏，重复操作不应增加同一来源。

## 权限与隐私

插件仅申请 `storage`、`alarms`、`declarativeNetRequest`，以及 `x.com`、`twitter.com`、`base-api.feishu.cn`、`t.co`、`github.com` 的 HTTPS 主机权限。运行时代码本地打包，不加载远程脚本。

授权码保存在当前 Chrome 配置文件的本地存储，仅可信扩展上下文可读取；不会传入 X 页面、任务快照、导出或 Chrome 同步。授权码用于请求飞书接口，本机存储不是加密保险箱。请勿把授权码、请求头或含凭证截图提交到仓库或 Issue。

本版每帖最多 20 个仓库，完整查重最多 5,000 行／20 MiB，单次活动预算 120 秒。超限停止写入并保留任务。

## 开发

使用 TypeScript、原生 DOM 和 esbuild，扩展采用 Manifest V3。

```sh
npm run typecheck
npm run build
npm run check:manifest
```

本次公开快照包含源码和构建检查。本机的 41 项回归测试暂未纳入公开文件，`npm test` 需要这些本机测试文件；下载源码后先运行上述类型、构建和 Manifest 检查。

```text
src/
  sources/x/          帖子和 Article 结构读取
  domain/            快照、仓库归一和来源回执
  destinations/feishu/  接口、分页和字段映射
  background/        串行同步与任务恢复
  storage/           本机任务及连接设置
  content/           帖子旁按钮和页面生命周期
  ui/                设置、弹窗和任务详情
static/              扩展页面
scripts/             构建与 Manifest 检查
docs/FIELDS.md       飞书字段说明
```

## 常见问题

**配置保存后还需要填写授权码吗？** 已保存时输入框留空会沿用原凭证；输入新值并保存可替换。设置页不会重新显示已存完整授权码。

**报“接口记录格式不兼容”怎么办？** 本版已兼容完整空表响应省略 `items` 的情况。先确认扩展已重新加载；若仍失败，只反馈错误文字中的 `items`／`has_more`／`total` 形态，不附完整响应或凭证。

**帖子已加书签，为什么 Favorites 没有显示已收藏？** 插件只认飞书表中的仓库和来源回执，X 书签不是同步证据。

**能多人共用或跨设备吗？** 本版没有共享服务端或远端唯一约束，当前按单用户使用验证。
