# Favorites 字段

在自己的飞书多维表格中建立下列 16 列。插件检查字段类型并通过字段 ID 建立映射，列名不同可手动选择对应列；所有列都要保留，读不到的来源值可以为空。

| 字段 | 类型 | 内容 |
|---|---|---|
| 仓库名称 | 文本（建议主字段） | owner/repo |
| GitHub 链接 | 超链接 | 归一后的仓库根地址，供去重 |
| 帖子原文 | 文本 | 实际包含仓库的来源正文，不生成摘要 |
| 原帖链接 | 超链接 | 上述正文所属帖子的地址 |
| 博主名称 | 文本 | 来源作者的显示名称 |
| 博主账号 | 文本 | 来源作者的 @账号 |
| 发帖时间 | 日期时间 | 来源帖精确时间，读不到则留空 |
| 入口帖子链接 | 超链接 | 点击收藏时所选帖子 |
| 入口帖原文 | 文本 | 入口正文 |
| 引用帖链接 | 超链接 | 直接引用的一层地址 |
| 引用帖原文 | 文本 | 实际读取到的引用正文 |
| 引用关系 | 单选 | 无引用／有一层引用／纯转发／待核对 |
| 链接位置 | 单选 | 入口帖／引用帖／两者 |
| 采集时间 | 日期时间 | 收藏时刻，与发布时间分开 |
| 采集状态 | 单选 | 已读取当前展示内容／部分缺失／待核对 |
| 来源记录 | 文本 | 追加的版本化来源证据；保留人工内容 |

单选值需与上述文字一致。旧版 bitable 接口下文本类型为 1、超链接为 15、日期为 5、单选为 3；插件以实际返回类型校验。

同仓库的新来源只追加到“来源记录”，不会覆盖已有人工作品介绍、作者等主字段。仓库只在引用里时，“帖子原文”和主作者使用引用来源，入口信息另行保留。
